# Research findings: 26 October 2026

**What this is.** Fact-finding done before Phase 0. It covers the plan's open items and the question that motivated the project: is there a real, unsolved problem here, or is this a learning exercise with a good portfolio piece at the end? Four research passes ran in parallel (AWIPS; ECCC model data; observations and non-ECCC models; market, role and cloud cost). The highest-stakes claims were then re-checked by hand against primary sources: the AWIPS source tree on GitHub, live Datamart directory listings, buoy status pages, the ECMWF open-data index, GRIB2 header bytes in downloaded files, and Oracle's free-tier page.

**Confidence labels.** CONFIRMED means a primary source or live data was checked today. LIKELY means a credible secondary source. UNVERIFIED means it could not be confirmed. NOT FOUND means it was searched for and not found; absence can't be confirmed, so treat these as "not found after searching", not as facts.

**Acronyms used below.** AWIPS: the forecaster workstation system (EDEX backend, CAVE front end). ECCC/MSC: Environment and Climate Change Canada and its Meteorological Service. GRIB2: the binary format model output comes in. NWP: numerical weather prediction. HRDPS, RDPS, GDPS: ECCC's high-resolution, regional and global deterministic models. RDWPS, GDWPS: ECCC's regional and global deterministic wave models. GEPS, GEWPS: ECCC's global atmospheric and wave ensembles. AIFS: ECMWF's AI forecast model. Hs: significant wave height.

## 1. The short answer

**The end-user problem is commercially solved.** StormGeo, DTN, the UK Met Office and DHI all sell probabilistic, ensemble-based weather-window forecasts out to about 15 days. WSP's own Met-Ocean group sells 24/7 marine forecasting. Building a competing product is not a contribution to the industry; it is evidence that you understand WSP's clients.

**What we didn't find published** (NOT FOUND after searching vendor sites, conference abstracts and GitHub):

- Reliability statistics for their own window decisions. DTN publishes vendor-claimed aggregate accuracy numbers with no metric named. The closest public item is a Met Office conference abstract (EMS 2021) on the economic value of probabilistic wave forecasts, not a product report.
- Any public comparison of AI weather models against traditional NWP for marine use. Only ECMWF itself reports that AIFS v2's wave forecasts have about 10% lower Hs error than IFS against satellite altimeters.
- A maintained open-source tool for live, ensemble-based window detection with buoy verification. The open-source tools that exist (metocean-stats, metocean-api, ORBIT, WOMBAT) work on historical hindcasts, not live forecasts.

Those three gaps, as far as public searching shows, are the uncommon part of Phases 3 and 4. They are not a product gap you can sell, but they are an honest "nobody shows this publicly" angle for the README and interview.

**The developer problem is real, specific and two months fresh** (CONFIRMED from source code; see section 2):

- Until September 2026, stock AWIPS silently discarded every GRIB2 field on a rotated latitude-longitude grid (grid definition template 3.1). The decoder's branch for template 1 was literally `pass`. Three of ECCC's flagship products sit on that grid: HRDPS, RDPS and the RDWPS national wave domain. A Canadian AWIPS shop therefore had to regrid ECCC output before ingest or write its own grid-coverage class.
- AWIPS 23.4.3-1 (released September 2026) adds a `RotatedLatLonGridCoverage`. It was written for NOAA's new RRFS model, not for ECCC. Today's HRDPS and RDWPS files have a rotation angle of 0, so they fit the new code path. But nothing ECCC-specific exists: the shipped centre-54 model tables describe old NOAAPort-era CMC grids, there is no rotated grid definition XML, no community recipe for Datamart feeds into EDEX, and the new class has no handling for grid-relative wind vectors, which ECCC's rotated-grid files use.
- So an open, documented "ECCC Datamart into AWIPS" ingest kit was not found in public. All of this applies to Unidata's open-source release. WSP may run a different or customized build and has almost certainly solved ECCC ingest internally, for example by regridding before ingest. The things that make it hard (the rotated grid, grid-relative winds, centre-54 parameter tables, the push feed) are exactly what this project's Python pipeline has to get right anyway. That is the gap worth aiming Phase 6 at, and it is squarely what the posting describes: decoders, parameter mapping, projections, ingestion.

**Verdict.** The project is suitable. Phases 1 and 2 teach the data; Phase 6 can now target a real, current, unsolved-in-public problem instead of a generic "touch AWIPS" exercise. The product (Phases 3 to 5) remains a learning vehicle and a demonstration of client understanding, and should be framed that way.

## 3. ECCC Datamart

All paths are under `https://dd.weather.gc.ca/today/`. All CONFIRMED from live listings and header parsing of downloaded files on 2026-10-26 unless marked.

**HRDPS continental.** Path `model_hrdps/continental/2.5km/{HH}/{hhh}/`. Real file: `20261026T00Z_MSC_HRDPS_UGRD_AGL-10m_RLatLon0.0225_PT006H.grib2` (1.9 MB, landed 02:58Z). Siblings `VGRD_AGL-10m`, `WIND_AGL-10m`, `WDIR_AGL-10m`, `GUST_AGL-10m`. Runs 00, 06, 12, 18Z; hours 000 to 048; the 00Z run was complete by about 03:15Z. Grid: template 1 (rotated lat-lon), 2540 x 1290, 0.0225°, south pole at about 36.1S 245.3E, rotation angle 0. **Resolution-and-component flags byte is 0x38, so u and v are relative to the rotated grid, not to true east and north** (I read the byte myself from the downloaded file). Compute direction from raw u/v and it will be wrong by the local grid rotation; use `WIND`/`WDIR` or rotate u/v, and check against `WDIR`. Gotcha: HRDPS encodes forecast time in minutes.

**RDWPS.** Domains live today: `erie`, `huron-michigan`, `national`, `ontario`, `superior`. **There is no Atlantic or Pacific folder**; the ocean waters are served by the `national` 2.5 km rotated grid (2536 x 1286, same pole as HRDPS, flags 0x38). Path `model_rdwps/national/2.5km/{HH}/` (flat, no hour subfolders). Real file: `20261026T00Z_MSC_RDWPS_HTSGW_Sfc_RLatLon0.0225_PT006H.grib2` (landed 03:23Z). Four runs a day in practice (the readme's "00, 12" is stale); hours 000 to 048 hourly. Variables: HTSGW (Hs), WVHGT, SWHFSWEL, SWHSSWEL, PWPER (peak period), PPERWW, MZWPER (mean zero-crossing period), PWAVEDIR, WVDIR, ICEC, UGRD, VGRD and others. No PERPW, SWELL, WIND or WDIR tokens.

**GDWPS (fallback).** `model_gdwps/25km/{HH}/`, regular 0.25° global grid, earth-relative vectors (flags 0x30), runs 00 and 12Z, hourly to 84 h then 3-hourly to 240 h.

**GEPS.** `ensemble/geps/grib2/raw/{HH}/{hhh}/`, old naming `CMC_geps-raw_UGRD_TGL_10m_latlon0p5x0p5_2026102600_P006_allmbrs.grib2`. One file holds 21 messages: control (perturbation 0) plus members 1 to 20. 0.5°, runs 00 and 12Z, 3-hourly to 384 h (6-hourly to 936 h on Monday and Thursday 00Z).

**GEWPS.** Live and **operational since Dec 1, 2021** (not experimental). `model_gewps/25km/{HH}/`, file `20261026T00Z_MSC_GEWPS_HTSGW_Sfc_LatLon0.25_PT006H.grib2` (15 MB), 21 members in one file, 0.25°, 3-hourly to 384 h, runs 00 and 12Z. Wave variables only, no wind.

**Usage policy** (CONFIRMED, quoted from eccc-msc.github.io/open-data/usage-policy/readme_en/): "For systematic data retrieval, the AMQPS service must be used." "Do not request directory listings to assess the availability of new data." "Use of wget or curl commands is reserved for ad hoc data retrieval only." Threshold: "86,400 requests per day or higher (about 1 request per second)". The plan's Phase 1 design of polling every 6 hours conflicts with the letter of this policy.

**AMQP.** Broker `amqps://anonymous:anonymous@dd.weather.gc.ca`, exchange `xpublic`, topic prefix `v02.post`, subtopic is the path with `/` replaced by `.`. The `sr3` (sarracenia) docs warn that directory names containing a period, like `2.5km`, change the topic hierarchy; test with `sr3 foreground` (LIKELY for the exact subtopic).

**Retention.** 30 days on dd.weather.gc.ca (date folders at the root); 52 days on the `hpfx.collab.science.gc.ca` mirror. `/today/` is an alias.

**Alternatives.** MSC GeoMet WMS `GetFeatureInfo` returns point values (tested: HRDPS wind speed and direction, GDWPS Hs at 46.5N 53.4W), but the policy says not to build archives from GeoMet, and RDWPS layers exist only for the Great Lakes. A third-party Zarr mirror of HRDPS exists on AWS Open Data (`s3://dynamical-eccc-hrdps`, dynamical.org); no official ECCC cloud mirror.

## 5. Other models

**ECMWF open data, AIFS** (CONFIRMED; I checked the `wave/` directory exists). AIFS v2 went operational on May 12, 2026 and added "ECMWF's first operational data-driven wave forecasts". The open-data index at `data.ecmwf.int/forecasts/{date}/{HH}z/aifs-single/0p25/` now has `oper/` and `wave/`; `aifs-ens/0p25/` has `enfo/` and `waef/` with control and 50 perturbed members. Wave parameters: swh, mwd, mwp and spectral bands; no peak period (pp1d). Both AIFS products: 0.25°, runs 00/06/12/18Z, steps 0 to 360 h by 6. Licence CC BY 4.0; only the last 12 runs are kept (about 3 days), so there is no AIFS archive. **This refutes the plan's assumption that AIFS has no wave fields.** IFS open data also moved to 0.1° on Oct 20, 2026, including waves (swh, mwd, mwp, pp1d). `herbie` 2026.9.2 routes AIFS only to `oper`/`enfo`; use the `ecmwf-opendata` client for the wave streams.

**NOAA on AWS Open Data** (CONFIRMED with real object keys). `noaa-gfs-bdp-pds`: `gfs.{date}/{HH}/atmos/gfs.tHHz.pgrb2.0p25.fHHH` plus `.idx`; wave at `gfs.{date}/{HH}/wave/gridded/gfswave.tHHz.{global.0p16|global.0p25|atlocn.0p16|gsouth.0p25|arctic.9km}.fHHH.grib2` plus `.idx`; the Atlantic 0.16° grid is hourly to 120 h then 3-hourly to 384 h. `noaa-gefs-pds`: `gefs.{date}/{HH}/atmos/pgrb2sp25/gepNN...` and the wave ensemble at `gefs.{date}/{HH}/wave/gridded/gefs.wave.tHHz.{c00|p01..p30|mean|spread|prob}.global.0p25.fHHH.grib2` plus `.idx`, 3-hourly to 384 h. `herbie` supports gfs, gfs_wave and gefs (including wave members). ## 8. What this changes in the plan

These were recommendations for Seum's decision. **Update, same day: all nine were adopted** and are built into the phases of `build-plan.md`. A second review then softened items 6 and 9 and relabelled absence claims; the plan reflects that too.

1. **Verification sites.** `sites.yaml` needs two kinds of site: forecast sites (the two Grand Banks points, where the product is aimed) and verification sites (44139 Banquereau Bank live offshore, SMA St. John's live coastal). Verify the Grand Banks points by hindcast against WSP's 2022 buoy using the GFS archive. This is a realistic operational lesson: observation networks are sparse and intermittent, and the system must say so rather than pretend.
2. **AMQP moves into Phase 1.** The usage policy requires it for systematic retrieval and forbids listing-based polling. `sr3` is the ECCC client; LDM is the AWIPS parallel.
3. **Grid-relative winds become a Phase 1 learn-first item and a unit test.** Direction from raw u/v on the rotated grid is wrong until rotated; compare against ECCC's own WDIR field. This is the posting's "troubleshoot projections, metadata, decoding" in one concrete bug, and it is the same issue the new AWIPS code has not addressed.
4. **Buoy ingest uses SWOB-ML XML plus NDBC text, not ERDDAP.** Parsing SWOB-ML is a small decoder in its own right and parallels AWIPS's observation decoders.
5. **Phase 4 compares waves as well as wind.** AIFS has a wave stream; fetch it with `ecmwf-opendata`.
6. **Phase 6 gets a real target.** Build the "ECCC Datamart into AWIPS" kit: grib model and grid XML for centre-54 Datamart products, an `sr3` or LDM feed configuration, and a check that HRDPS winds display correctly in CAVE. Validate what you can against GRIB headers and the public EDEX; rent an x86 VM for a weekend (about $10 to 20) if you want to run EDEX itself; write it up for the awips2-users list. No public equivalent was found, and it is the posting's job description. (Second review: the EDEX test became a stretch goal; the minimum is configuration validated against GRIB headers.)
7. **AWIPS touch and Java can move to Phase 2** as proposed: the public EDEX is open, CAVE has a Windows installer, python-awips is current.
8. **Cloud.** Stay on OCI; 2 OCPUs and 12 GB is enough. Upgrade to Pay As You Go on day one and set a budget alert. If ARM capacity fails for a day, use AWS t4g.small in ca-central-1 (near-free through 2026).
9. **Pitch update** (revised after a second review, which pointed out WSP has almost certainly solved this internally): "I hit the rotated-grid and grid-relative wind problem with ECCC data, saw stock AWIPS only gained rotated-grid support in September for a NOAA model, and worked out the ECCC configuration." Use the last clause only once it's true.
